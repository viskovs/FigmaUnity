# Внесение изменений

## Общие правила

1. Создавайте отдельную ветку от актуальной `main`.
2. Не добавляйте секреты, Figma tokens и локальные пути пользователей.
3. Сохраняйте обратную совместимость `schemaVersion`, либо добавляйте миграцию.
4. Не меняйте визуальную структуру Figma без явного действия дизайнера.
5. Unity Bridge не должен автоматически записывать файлы в `Assets`.
6. Project-specific логика должна приходить через catalog.

## Проверка Figma-части

```bash
node --check code.js
```

Затем импортируйте development plugin в Figma Desktop и проверьте сохранение
аннотаций, валидацию, импорт catalog, JSON download и Unity Bridge.

## Проверка Unity-части

Добавьте `UnityPackage/package.json` в чистый тестовый Unity-проект. Проверьте:

- компиляцию package;
- ответы `GET /health` только локально;
- создание inbox-файла через `POST /publish`;
- остановку listener при завершении Unity;
- отсутствие изменений в `Assets`.

## Pull request

Укажите решаемую задачу, изменения schema/catalog, способ проверки, влияние на
обратную совместимость и скриншоты, если менялся интерфейс.
